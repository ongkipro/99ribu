| DEC-005 | Accepted | The Berlapak snapshot is the real starting catalog and ships with the application as production catalog content, not fixture data. (1) Scope is catalog only: categories, products, fixed IDR 99,000 complete offers, bundle contents/components, publication and product photos; stock quantities, component costs and the 16 dummy orders are excluded and are entered later through real admin/receiving flows. (2) Source is a sanitized, reviewable dataset committed under `data/catalog/berlapak/`, generated deterministically from the raw snapshot by a local command; it carries public names only (no supplier names, HPP, stock or supplier/warehouse identities). The server runs one idempotent import command from that dataset at deploy time. (3) Photos are stored through the application storage module, content-addressed by SHA-256, outside `public/`, at the same path locally and on the server; DEC-003 stays (raw Berlapak images are never served). The S69 importer remains a local-only fixture tool (slice S80). (4) Live catalog (slice S81, owner decision 2026-10-22, amends (1)): the imported catalog is the live public catalog. Initial stock and component HPP are not committed; a separate operator step (`npm run catalog:initial-stock -- <target> <warehouse-id>`) reads the raw snapshot at run time and, as a temporary audited MFA owner, posts one `receive` movement per catalog stock item (`createMovement`, expected version 0) and one component cost version (`appendCostVersion`, expected version 0) only where none exists; it refuses before any write when the raw snapshot is not the dataset's `source_snapshot` or the catalog is not imported. A rerun or a later snapshot never receives again or overwrites HPP: differences are reported as drift and corrected through normal receiving/adjustment/cost flows. Snapshot stock spread over several supplier warehouses is received, per item, into the single warehouse the offers bind to (the import warehouse), because S80 offers fulfil from one default warehouse. Offers without assumptions receive the S69 defaults (packaging 1,000, provider fee 1,000, subsidy 5,000, returns reserve 1,000 IDR) in the same step; existing assumptions are kept. Publication remains the guarded import rerun or `publishProduct`. (5) The public storefront (home, categories, search, header, PDP, feed) shows only current publications; home merchandises the newest publications and the departments with most published products, never fixed SKUs or slugs. Taking a product off sale is an immutable, audited `publication_withdrawal` of the current publication (migration 0029; republishing is an ordinary publication), honoured by every public and sale reader; non-catalog publications are withdrawn by `npm run catalog:withdraw -- local --apply` (dry run by default), never by deletes or SQL edits. Browser suites share the local database, so the test runner withdraws, after every browser run, the non-catalog publications that synthetic or removed principals made during that run; operator publications and the catalog are never swept. | Owner decisions 2026-10-22 |
