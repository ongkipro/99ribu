## Goal

Every state the provider-backed flow can produce has a clear, concrete Indonesian message and a recoverable screen, on the 2026-11-03 field system (static labels, 48 px controls, 16 px text, no mobile zoom). Logic stays in the server; this slice is states and words.

## Evidence

- Error codes already produced by the shipping seams: `SHIPPING_RATE_TIMEOUT` (503), `SHIPPING_RATE_UNAVAILABLE` (503), `SHIPPING_RATE_INVALID` (503), `SHIPPING_RATE_EXPIRED` (409), `NO_SUPPORTED_ROUTE` (422), `COD_UNAVAILABLE` (422), `DESTINATION_UNAVAILABLE` (422), `DESTINATION_POSTCODE_MISMATCH` (422), `SHIPPING_UNAVAILABLE` (503), `ROUTE_UNCONFIGURED` (422, local fixture).
- Payment outcomes: attempt `pending`, provider `rc` rejected (`rejected`), unknown outcome after a timeout (`responded_at` null, reconciliation replays), `AUTOLARIS_AMOUNT_MISMATCH` / `TOTAL_MISMATCH`, expired order with a final advice read.
- The checkout already has a help section, `checkout-caution` alerts, "Hasil tindakan belum diketahui" recovery and a draft that survives errors (`checkout-forms.tsx`, `CheckoutHelp`).
- Field system and no-zoom evidence: `src/app/styles/03-checkout.css` (labels 14 px, controls 48 px, 16 px text), `tests/browser/storefront-floating-labels.test.ts` (kept filename).
- AGENTS.md: concrete Indonesian UI copy without filler, SVG icons only, no emoji, rendered browser evidence, independent design review when applicable.

## Recommendation

Reuse existing strings and components first (grep the checkout components for the codes above and for the recovery copy); add only what is missing. Proposed copy, to be checked against existing wording before use:

| State | Where | Copy (draft) |
|---|---|---|
| searching area | region field | "Mencari wilayah…" |
| no area found | region field | "Wilayah tidak ditemukan. Coba nama kelurahan atau kode pos lain." |
| provider unreachable / timeout | shipping section | "Ongkir belum bisa dihitung. Isian Anda tersimpan. Coba lagi sebentar lagi." + retry button |
| no courier for the destination | shipping section | "Belum ada kurir untuk tujuan ini. Periksa alamat atau pilih wilayah lain." |
| COD not available | payment section | "COD tidak tersedia untuk tujuan ini. Pilih transfer atau VA/QRIS." |
| quote expired | review | "Ongkir sudah berubah. Hitung ulang sebelum membuat pesanan." |
| payment instruction ready | order page | existing receipt copy; show the fee line when the provider fee is displayed |
| payment outcome unknown | order page | "Hasil pembayaran belum kami terima. Jangan bayar lagi. Periksa status pesanan." |
| channel unavailable | payment section | "Metode ini sedang tidak tersedia. Pilih metode lain." |

Rules: one sentence says what happened, the next says what to do; never show provider codes, URLs or raw errors; keep the draft; keep keyboard order and `role="alert"` or `role="status"` as the existing components do; every control stays ≥ 16 px; no horizontal overflow at 390/768/1440.

Do not add a "mode" banner in buyer screens. If provenance must be visible, show it in staff views only (S164 open question).

## Risks and escalation

- Copy that promises more than the provider guarantees (for example "pembayaran berhasil" before a settled advice). Review each sentence against the state machine.
- A visual design review (design-taste, ui-validation) is required by AGENTS.md; self-review is invalid.
