## Goal

Close the stand-in's fidelity gaps that 99ribu's slices depend on, in the repository that owns the stand-in (D4), without changing what AdsBookCMS itself relies on.

## Evidence

Stand-in file: `~/Projects/adsbookcms/scripts/dev-providers.ts` (`dp:N` below); drift test: `src/lib/dev-providers.test.ts:14-86` (drives the real `MengantarClient` and `AutoLarisClient`, `startDevProviders(0)`).

- No `POST /api/h2h/create_payment`; only `submit` (`dp:154-180`). The official guide has both; they must not be called for the same checkout.
- `reff_id` is neither echoed nor deduplicated; ids are `Date.now()` based (`dp:154-180`).
- No failure or delay levers; the only dev levers are `GET /__dev/autolaris/payments` and `POST /__dev/autolaris/pay?transaction_id=` (`dp:193-201`). No expiry or failure transition. No 401/403/`rc 01`/`rc 07`.
- Advice: unknown id `rc 14`, unpaid `rc 02 PENDING`, paid `rc 00 ket PAID, data {awb: ""}` (`dp:181-188`), an invented settled shape (the docs say none is published).
- Courier keys differ from the real ones and `courier` is ignored; `unsupported` is never true (`dp:21-33`, `dp:244-254`).
- Any key or bearer is accepted; state is in memory; `GET /order` and `POST /order` pretend `isPaid: true`.
- The drift test proves only that the clients parse what the stand-in sends (circular for the settled shape).

## Recommendation (smallest change that unblocks S165 and S166)

1. **`create_payment`** per the official request and response: fields `reff_id, channel_code, customer_id, customer_name, customer_phone, customer_email, expired (YYYYMMDDHHMMSS), amount, callback_url`; answer `rc 00` with `data {trx_id, virtual_account, qr, payment_code, url, amount, admin, total}` where exactly one instruction field is non-empty. Add a `fee_mode` switch so both `total = amount` (99ribu's expectation) and `total = amount + admin` (the docs' sample) can be served.
2. **`reff_id`**: echo it and dedupe: the same `reff_id` returns the same `trx_id` (a configurable "provider ignores duplicates" mode lets a test show the gap).
3. **Fault levers** (loopback only, under `/__dev/`): per-route `timeout-before`, `timeout-after`, `http 5xx`, `malformed body`, `rc 01`, `rc 07`, `401`, with a count so a test can fail once and then succeed; plus `expire` and `fail` for a payment and `delay_ms`.
4. **Settle lever** that can answer the exact shape 99ribu's placeholder expects (`rc 00`, `data {status: "PAID", amount, paid_at}`) **flagged as invented**: response header `x-stand-in: 1` and a comment; never described as the real contract.
5. **Courier keys**: serve the real keys (`JNE`, `SiCepat`, `SAP`, `iDexpress`, `JT`, `lion`, `anteraja`, `spx`, `pos`) and honour `courier` (flat object for a single courier, `400 Invalid courier` for an unknown one); add switchable `unsupported`, `unsupportedOriginSpx` and `unsupported_cod` cases. Keep the fake price formula but mark it fake in the header.
6. **Optional auth strictness**: reject a missing bearer with `401` when a flag is set, so credential-error paths can be exercised.
7. **Provenance** on every response: header `x-stand-in: 1` (a body field could change what clients parse).
8. Update `dev-providers.test.ts` for every new behaviour; AdsBookCMS's own clients must keep passing unchanged.

### 1. `POST /api/h2h/create_payment` with `fee_mode`

- **Today**: no route; falls to `404 {error:"not found"}` (`dp:293`). Only `submit` (`dp:154-180`), which answers `total = grand_total` and derives `biaya_admin` from AdsBookCMS's own fee table (`calculatePaymentAdminFee`, `dp:160`).
- **Change**: new branch before `dp:181`. Request (guide §4): `reff_id, channel_code, customer_id, customer_name, customer_phone, customer_email, expired (14 digits), amount (digit string), callback_url`. Missing/invalid field or non-positive amount: `200 {rc:"01"}` (meaning documented; `ket` text and HTTP status `unpublished`). Channel outside the `list_payment` set (`dp:151`): `200 {rc:"07"}` (documented for this endpoint; `ket` `unpublished`). Success: `{rc:"00", ket:"Sukses", data:{trx_id, virtual_account, qr, payment_code:"", url:"", amount, admin, total}}`, numbers as numbers, exactly one of `virtual_account`/`qr` non-empty (QRIS gets `qr`, VA channels get `virtual_account`). `admin` reuses `calculatePaymentAdminFee` (per-account fees are `unpublished`). `fee_mode`: `added` gives `total = amount + admin` (docs sample 11000+3000=14000); `inclusive` gives `total = amount` (99ribu's `AUTOLARIS_TOTAL_MISMATCH` check, `autolaris.ts:156`). Set via `POST /__dev/autolaris/config?fee_mode=added|inclusive`. Do not enforce https on `callback_url` (99ribu sends a loopback URL); never call it (callback contract `unpublished`). Store the record in the existing `payments` map with `source:"create_payment"`, `reff_id`, `receiver = customer_name`, so `advice` (by `trx_id`) and `GET /__dev/autolaris/payments` work unchanged.
- **Files**: `scripts/dev-providers.ts`; new tests.
- **Test impact**: none on existing cases (new route). `dev-seed.ts:465-471` filters the payments list by `paid/receiver/total`; extra fields are additive.
- **Risk**: the fee table is AdsBookCMS product code imported by the stand-in (`dp:16-17`), so an AdsBookCMS fee change shifts 99ribu's figures: S167 must pin the `HEAD`. The default `fee_mode` decides whether 99ribu S166 passes out of the box; that is A2, an owner/S97 question, not a stand-in choice.

### 2. `reff_id` echo and dedupe

- **Today**: `transactionId = Date.now() + sequence` (`dp:161`); `reff_id` is neither stored, echoed nor deduped.
- **Change**: `create_payment`: a `Map<reff_id, trx_id>`; same `reff_id` returns the same `trx_id` and the original `amount/admin/total` (body differences on replay: `unpublished`; recommend answering the original record). Mode `POST /__dev/autolaris/config?duplicates=dedupe|ignore` (`ignore` = new `trx_id` per call, shows the double-bill gap). The provider's duplicate rule is `unpublished` (guide §9 Q7; the Create Resi "not same day" rule is not stated for this endpoint), so a third `reject` mode would also be invented: leave it out unless S166 needs it. Do **not** add `reff_id` to the `create_payment` response body (not in the documented sample); expose it in `GET /__dev/autolaris/payments`. `submit`: add `data.reff_id` (documented, `h2h-api.md` §7) but keep it **undeduped** by default.
- **Files**: `scripts/dev-providers.ts`; new tests.
- **Test impact**: existing test uses distinct `reffId` 10001/10002 (`test.ts:62,83`); unaffected. `parseAutoLarisPaymentResponse` ignores an extra `reff_id`.
- **Risk**: AdsBookCMS derives `reff_id` from the order number (`autolaris-payment.ts:119-125`). A standalone `dev:providers` kept alive across a D1 `--reset` would replay `INV-10001` and get a stale transaction if `submit` were deduped; hence no dedupe on `submit`.

### 3. Fault, settlement and expiry levers

- **Today**: only `GET /__dev/autolaris/payments` and `POST /__dev/autolaris/pay?transaction_id=` (`dp:193-201`); no failure, delay, expiry or auth check; any bearer accepted. Advice: unknown `rc 14`, unpaid `rc 02 PENDING`, paid `rc 00 ket PAID data {awb:""}` (`dp:181-188`).
- **Change** (loopback only: server binds 127.0.0.1, `dp:301`; state per server instance):
  - `POST /__dev/fault?route=<list_payment|create_payment|submit|advice|estimate>&kind=<k>&count=<n≥1, default 1>[&delay_ms=<n>][&status=<500-599>]`; `GET /__dev/faults`; `DELETE /__dev/faults`. Unknown route/kind answers 400 (no silent typo). Each matching request decrements `count`; at 0 the fault clears, so "fail N times then succeed" works.
  - Kinds: `timeout-before` (hold the socket `delay_ms`, default 15000 > the 10 s client timeouts, then destroy it; nothing recorded); `timeout-after` (record the payment/dedupe entry first, then hang; create routes only); `http5xx` (`status`, default 503, body `{}`); `malformed` (200, body `not json`); `rc01`, `rc07` (200 + `rc`; documented only for `create_payment`, so allow them only there); `http401` (status documented as "cek key/IP"; body `unpublished`, send `{}`); `delay` (wait `delay_ms`, then the normal answer). For `estimate`, only `timeout-before`, `http5xx`, `malformed`, `delay`; Mengantar `X001` exists but its HTTP status is `unpublished`.
  - Payment state: `POST /__dev/autolaris/expire?transaction_id=` and `/fail?transaction_id=`. The advice answer for expired/failed is `unpublished`: use a non-`00`/non-`02` code (e.g. `rc "99"`, `ket "EXPIRED"`/`"FAILED"`), marked invented in a comment. No automatic expiry from `expired` (timezone `unpublished`).
  - Settle shape: optional `&shape=status` on the existing `pay` lever; advice then answers `{rc:"00", ket:"PAID", data:{awb:"", status:"PAID", amount:<record total>, paid_at:<ISO>}}`, which both clients accept (AdsBookCMS reads `ket`, `autolaris-client.ts:507-512`; 99ribu reads `data.status/amount/paid_at`, `autolaris.ts:28-35`). **Invented**: no settled example is published. Without `shape` the answer stays byte-identical to today.
- **Files**: `scripts/dev-providers.ts`; new tests; optional `scripts/dev-local.ts:108` banner line.
- **Test impact**: none while levers are unarmed. New timing cases need `server.closeAllConnections()` in teardown (hung sockets otherwise keep the run alive) and short `delay_ms` (BUILD-LOG entry near line 8297 already records a timing-sensitive flake in this file).
- **Risk**: a 99ribu run arming faults on a **shared** 8788 instance would break a running AdsBookCMS `dev:local` store; 99ribu must start its own instance (S167). Invented codes must never be quoted as contract (header, comment, 99ribu briefs).

### 4. Real Mengantar courier keys, `courier` parameter, switchable flags

- **Today**: `COURIERS` = `JNE, SiCepat, J&T, SAP, Anteraja, IDexpress, Paxel, lion, pos, spx` (`dp:21-33`); `courier` ignored, always keyed (`dp:244-254`); `unsupported:false` always, `unsupported_cod` true only for Paxel (`dp:98-99`).
- **Callers checked**: AdsBookCMS matches couriers by a normalised key (`courier-rules.ts:8-9`, lowercase, non-alphanumerics stripped), so `JT`≡`J&T`, `iDexpress`≡`IDexpress`, `anteraja`≡`Anteraja` against the seeded rules (`install.ts:55-66`); display names normalise the same way (`courier-names.ts:22`); `ExpeditionSettings.tsx:66-77` keys logos by **rule** code (DB), not estimate key; `dev-seed.ts:416-436` uses whatever the estimate returns; `mengantar-client.ts:603-627` skips `/cargo/i` keys and drops `unsupported`/`unsupportedOriginSpx` rows; product code only ever sends `courier=all` (`ongkir.ts:61`, client default `:584`). Tests that use other courier codes (`courier-rules`, `courier-names`, `rate-check`, `public-store`, `courier-bootstrap`, `mengantar-client`) use their own fixtures, not the stand-in.
- **Decision: REPLACE** `J&T`→`JT`, `IDexpress`→`iDexpress`, `Anteraja`→`anteraja`; **ADD** `SAPLite` (optionally the four cargo keys; both clients skip them). Adding alongside would emit two rows that normalise to `jt`; `selectQuotedRate` (`courier-rules.ts:41-44`) requires exactly one match without a service index, so a J&T checkout would fail. **Paxel**: not a real key (Mengantar docs `02-couriers-and-rules.md:42`) but asserted by `test.ts:26`; keep it as a marked stand-in-only key (99ribu hides it, `mengantar.ts:18,28`) unless the owner accepts changing that assertion. `devReceiverScore` keeps `J&T` (`dp:71`): different endpoint, out of scope.
- **`courier` param**: `all` (or absent: docs default is `JNE`, but keep today's keyed answer when absent) unchanged. Accepted single names are the shipment names `JNE, SiCepat, Sap, iDexpress, JT, lion, anteraja, pos` (`01-api-reference.md:243`); answer the matching entry (`Sap`→`SAP` row) as `data`. HTTP 200 is documented; the **flat body shape is `unpublished`** (asserted only by AdsBookCMS's client comment, `mengantar-client.ts:597`). Anything else, including every SPX spelling and `SAP`: `400 {success:false, message:"Invalid courier"}` (documented). `Ninja`: `400 {success:false, message:"Courier is not available", code:"COURIER_DISABLED"}` (documented). No current consumer in either repository sends a single courier, so this part is fidelity only.
- **Flags**: `POST /__dev/mengantar/estimate?courier=<key>&flag=unsupported|unsupportedOriginSpx|unsupported_cod&value=true|false`, `DELETE` to reset; `unsupportedOriginSpx` only on `spx` (docs). Defaults stay false/as today, or AdsBookCMS drops rows in its own checkout.
- **Files**: `scripts/dev-providers.ts`; new tests; README line if keys are listed.
- **Test impact**: `test.ts:25` (JNE) and `:26` (Paxel) unaffected with the above; no other test reads `estimateDevRates`.
- **Risk**: live JNE/SiCepat omit `unsupported_cod` (99ribu observation, `mengantar.ts:10`); the stand-in always sends it. Optional `omit` lever value; otherwise record as accepted drift.
