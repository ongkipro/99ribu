## Goal

Let the **local** profile (and the isolated test target) name one loopback origin where a provider stand-in listens, with the same strictness the profile applies today to everything else. With the variable unset nothing changes.

## Evidence

- `readLocalConfig` (`src/config/local.ts:46`) requires `APP_ENV=local`, `APP_ORIGIN=http://127.0.0.1:3099`, every adapter env equal to `simulated`, `EXTERNAL_DISPATCH=disabled`, and refuses any non-empty env name matching `providerKey` (`:60`): `^(?:NEXT_PUBLIC_)?(?:VIRGO|MENGANTAR|META|FACEBOOK|GOOGLE_ADS|TIKTOK|SMTP|RESEND|SENDGRID|TWILIO)_`.
- `AUTOLARIS` is **missing** from that regex but present in the production one (`src/config/runtime.ts:11`), while `README.md` (~244) says local refuses it. Today a real `AUTOLARIS_API_KEY` can reach a local run.
- `readTailnetOrigin` (`:36`) is the existing pattern for one extra, strictly validated origin; copy its shape.
- Production (`readProductionConfig`, `runtime.ts:111`) refuses every provider variable except the two Mengantar names; `productionShipping` accepts only `https://api-public.mengantar.com` exactly and a 16–128 character key.
- No central egress guard exists (`EXTERNAL_DISPATCH` is only compared to `disabled`).
- Config tests live in `tests/config.test.ts` (local refusals ~47–67, tailnet ~86–110, production ~180–275) and run under `npm test` (file list in `package.json`).

## Recommendation

1. Add `readLocalProviderOrigin(env)` next to `readTailnetOrigin`: reads `LOCAL_PROVIDER_ORIGIN`; empty or unset gives `null`; otherwise it must match `^http://127\.0\.0\.1:([0-9]{4,5})$`, the port must be 1024–65535 and not 3099, and `new URL(value).origin === value` (no path, query, userinfo, trailing slash, `localhost`, `127.0.0.2`, IPv6, tailnet address or https).
2. Return it as `providerOrigin` from `readLocalConfig` (frozen, `null` by default). `trustedOrigins` stays unchanged: the stand-in is an outbound target, not a browser origin.
3. Keep every adapter env at `simulated` and `EXTERNAL_DISPATCH` at `disabled`. The variable switches *where* the existing seams call, not which adapter family is selected.
4. Add `AUTOLARIS` to the local `providerKey` regex. The stand-in needs no key; the Mengantar path key and the AutoLaris bearer are the literal `local`.
5. `readProductionConfig` refuses any non-empty `LOCAL_PROVIDER_ORIGIN` with a fixed message. Check `compose.yaml` and `tests/container.test.ts` (which pins compose env) so the variable can never be passed in production.
6. Document the variable once, commented, in `.env.example`.
7. One reader serves web, worker and scripts: they already call `readRuntimeConfig`; add no second parser.

Why a new variable name: the forbidden `MENGANTAR_` prefix and `AUTOLARIS_BASE_URL` (https only) would force loosening existing rules. A distinct `LOCAL_` name keeps the old rules intact and is easy to refuse in production.

## Scope

In: `src/config/local.ts`, `src/config/runtime.ts` (production refusal), `.env.example`, `tests/config.test.ts`, `package.json` only if a new unit test file is added.
Out: any caller of the origin (S164, S166), any migration, any change to adapter env values, `compose.yaml` behaviour.

## Allowed and protected paths

Allowed: `src/config/**`, `.env.example`, `tests/config.test.ts`, `tests/container.test.ts` (assertion only). Protected: `src/db/**`, `migrations/**`, `src/modules/**`.

## Test plan

- Accept: `http://127.0.0.1:8788`, `http://127.0.0.1:4000`.
- Refuse (fixed message, never echoing the value): `http://localhost:8788`, `http://127.0.0.2:8788`, `http://[::1]:8788`, a tailnet address, `https://127.0.0.1:8788`, a path, a trailing slash, userinfo, port 3099, port 80, port 70000, a space, an empty-looking value with whitespace.
- Local with `AUTOLARIS_API_KEY` set refuses; local with `LOCAL_PROVIDER_ORIGIN` unset behaves as before (existing assertions unchanged).
- Production with `LOCAL_PROVIDER_ORIGIN` set refuses; production with a loopback `MENGANTAR_BASE_URL` still refuses.
- `--case=T-23` and `npm test` PASS.

## Risks and escalation

- Loosening a guard is an R3 change to a security boundary: an independent review must read the final regexes and the production refusal.
- `STATUS.md` says the AutoLaris live client is prepared for "env `AUTOLARIS_API_KEY`, optional `AUTOLARIS_BASE_URL`, local only". Adding `AUTOLARIS` to the regex removes that local path; confirm the owner accepts this (it matches the README and S97 is the planned way to use a key).
- Escalate if a script or fixture already sets an `AUTOLARIS_*` variable locally.

## Done when (runnable)

`npm test` and `npm run test:integration -- --case=T-23` PASS with the new refusal cases listed above; a local start without the variable shows no behavioural diff; independent review recorded against the final surface.
