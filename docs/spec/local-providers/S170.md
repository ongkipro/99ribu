## Goal

Refuse quotes for excluded provinces or areas and hide COD for COD-disabled provinces, driven by data the owner controls, not by code.

## Evidence (AdsBookCMS reference)

- `src/lib/excluded-area.ts` keeps a keyword table per excluded province (provinces, abbreviations, typical cities) and `detectExcludedAreaInText` scans the **typed address text** as a second guard, because mobile IP geolocation often misplaces buyers (a Papua buyer detected in Jakarta). It reports only provinces that are in the configured excluded list.
- `getCodDisabledProvinces` (`src/lib/form-mode.ts:29-34`) maps stored province codes to lower-cased names; `resolveFormModeFromProvince` returns the `full` form for an excluded province and `middle` otherwise.
- 99ribu already knows the province: a destination is a chosen `app.shipping_area` row with `province`, `city`, `district`, `subdistrict` (`Destination`, `destinations.ts:13`). No text scan is needed.
- Refusal seams that already exist: `buildShippingPlans` raises `422 NO_SUPPORTED_ROUTE` or `422 COD_UNAVAILABLE`; the COD flag per rate drives COD visibility.

## Recommendation (when the owner decides)

1. **Data, not code:** a small table (for example `app.shipping_exclusion`: scope `province|city|district`, area name or id, `refuse_quote boolean`, `cod_disabled boolean`, reason, version, audit columns), editable by the owner with an audited change, read in the quote path. It needs a migration and an R3 review.
2. **Match on structure:** compare the chosen destination's province (and city or district for finer scopes) to the table. Do not port the keyword scan; it exists to compensate for unreliable geolocation, which 99ribu does not use.
3. **Effects:** `refuse_quote` → the quote is refused with the existing `NO_SUPPORTED_ROUTE` code and a fixed Indonesian message (S168 pattern); `cod_disabled` → COD false on every rate for that destination (the same flag the provider path uses).
4. **Snapshot:** the exclusion version used is frozen into the quote like other policy versions so an old quote stays explainable.
5. **Admin:** list, add, retire and history in the staff console (admin-product-ux contract), not a config file.

## Scope

In: the table, the quote-path check, admin editing, tests, copy.
Out: IP geolocation, text scanning, per-buyer exceptions.

## Needs from the owner before work starts

- The list of excluded provinces and areas and, separately, the COD-disabled ones; reasons; wording for the buyer.
- Whether an excluded buyer gets a contact route instead of a dead end.

## Risks and escalation

- Over-blocking legitimate buyers; start with provinces, add finer scopes only on request.
- A wrong list is a revenue and trust problem: show the list and its effect in admin before activation.
- Escalate: any migration or policy text.

## Done when (runnable, once decided)

Each excluded province refuses a quote with the fixed message; each COD-disabled province hides COD on every rate; the list is data editable with an audit record; the frozen exclusion version is visible on the quote; `PR-3`, `PR-4` and the new case PASS; independent review recorded.
