# S164 — Shipping in local-provider mode (destinations and the S95 adapter)

|---|---|

## Goal

With `LOCAL_PROVIDER_ORIGIN` set, the local checkout resolves destinations from the real kelurahan catalogue and gets rates from the stand-in through the **same code path production uses**. With it unset, nothing changes.

## Evidence

- `destinationSource()` (`src/modules/shipping/destinations.ts:16-20`) returns `TEST-ONLY` for every non-production target; `findDestination` then reads the fixture (ids `^[a-z0-9-]{1,100}$`, labels "Contoh ..."). In production it reads `app.shipping_area` (24-hex ids).
- `mengantarRateAdapter` (`mengantar.ts:56`) gets `{baseUrl, apiKey}` from `productionShipping(process.env)` (`:44`) and calls `${baseUrl}/api/public/${apiKey}/order/estimate` (`:49`) with a 5000 ms fetch; cache 5 min, price validity 10 min, at most 1000 entries, 300 fetches a minute per process.
- `rateSeam` (`quotes.ts:23-27`) picks `mengantarRateAdapter` when `destinationSource() === 'mengantar'`, otherwise `localRateAdapter`; `buildShippingPlans` refuses an adapter whose `source` differs from `destinationSource()` (`quotes.ts:32`).
- The database guard `app.guard_checkout_quote` (migration 0042) admits plan and option `source` values `TEST-ONLY` and `mengantar` only. A third value needs a migration.
- A rate needs the warehouse `provider_area_id` (origin); a null origin yields `[]`.
- The stand-in's `/address/search` cannot serve this form: `_id: "dev-area-N"`, no kelurahan, `ZIP_CODE: ""`.
- Existing tests already swap `process.env` to a synthetic production env (`tests/integration/shipping-mengantar.test.ts:12-18`) and inject adapters (`rateSeam.adapter`).

## Recommendation

**Reuse production's path, change only the config source.** No new source value, no migration.

1. Add one function, e.g. `shippingProvider()`, returning `{baseUrl, apiKey}`: production → `productionShipping(process.env)`; local or test with `providerOrigin` → `{baseUrl: providerOrigin, apiKey: 'local'}`; otherwise `null`. `mengantar.ts:44` calls it instead of `productionShipping` directly.
2. `destinationSource()` returns `'mengantar'` when `providerOrigin` is set on a non-production target (so `findDestination`, `initialDestinations` and `searchDestinations` use the `app.shipping_area` branch, and `rateSeam` picks `mengantarRateAdapter`). Production logic stays first and unchanged.
3. Mark provenance in `Rate.version`: `mengantar-estimate-v1+stand-in` when the base is the stand-in (rate ids hash the version, so they differ). A quote built in this mode is then recognisable in the data and in admin views without a schema change.
4. Local data prerequisite: load `data/shipping/mengantar-areas.json.gz` into the local `app.shipping_area` and map the warehouses (`provider_area_id`) with the existing tools (`scripts/mengantar-areas.ts`, `resolve-warehouses --apply`; read the README registry for exact syntax before running; they are production-rollout commands in `STATUS.md`). This writes to `99ribu_local`, so it needs the owner's go-ahead, is keyed by `dataset_version`, and must be reversible (a documented delete by that version).
5. Add the stand-in base to the in-process cache key so a process never mixes stand-in and real entries (cheap, avoids a confusing test failure).
6. Keep the TEST-ONLY fixture as the default and as the test source; S164 adds a mode, it removes nothing.

Alternatives rejected: the stand-in's `/address/search` (no zip or kelurahan, fake ids); a third `local-provider` source (migration 0046 for a marker the version field already gives); labelling the adapter `TEST-ONLY` while using DB areas (the guard and `findDestination` disagree on id shape).

## Test plan

- Unit/contract with an **in-test HTTP server** that returns the stand-in's recorded shapes (so S164 does not depend on the other repository): estimate keyed by courier, flags, a 5xx, a malformed body, a slow answer.
- Mode on: a kelurahan from the catalogue resolves; id and postal code reach the quote and the order snapshot unchanged; a forged or stale 24-hex id is refused (`DESTINATION_UNAVAILABLE`); a postal-code mismatch is refused (`DESTINATION_POSTCODE_MISMATCH`); the quote's rates carry the `+stand-in` version.
- Mode off: the fixture path and `--case=PR-3` and `PR-4` behave exactly as before; production env with a loopback origin refuses (S163 test reused).
- Egress: in mode on, a fetch to any host other than the configured origin fails the test.

## Risks and escalation

- A `mengantar`-labelled quote made locally looks like a production quote. Mitigation: the `+stand-in` version suffix and the fact the local database never leaves the host. Escalate if a flow copies local data elsewhere.
- Loading 79,391 rows changes the local database; verify the load is idempotent and reversible before running.
- Rate limits: `destinationSearchPerAddress` 30/min and global 600/min apply to the search route; do not raise them for this mode.
- Escalate on any need for a migration.
