## Goal

One documented way to start the stand-in, one command that proves it is reachable and speaks the expected shapes, and one owner of its code. Missing dependency must fail loudly, never skip (AGENTS.md: required unavailable dependencies fail).

## Evidence

- The stand-in is `~/Projects/adsbookcms/scripts/dev-providers.ts`: loopback only, port from `DEV_PROVIDERS_PORT` (default 8788; `Number(...) || 8788`, so `0` cannot be passed through the environment), in-memory state lost on restart, no key check (the Mengantar key in the path and the AutoLaris bearer are ignored), unauthenticated `/__dev/*` levers, ids seeded from `Date.now()`. `startDevProviders(0)` exists for an ephemeral port but only by import.
- AdsBookCMS starts it through `npm run dev:providers`, or through `dev:local` which sets `MENGANTAR_BASE_URL` and `AUTOLARIS_BASE_URL` to the same origin (`dev-local.ts:67-83`) and uses port + 1.
- Its repository is currently on branch `fix/landing-list-hides-aliases`, so "latest" is not stable; the checkout can move under 99ribu.
- `GET /` returns an index of what is simulated; any unsimulated path answers 404 `dev-providers: ... is not simulated`.
- 99ribu check registration pattern: `scripts/check-tests.ts` (`validSelectors`, file mapping) and the README acceptance command registry.

## Recommendation

1. **Call, do not copy** (D4). 99ribu runs the AdsBookCMS stand-in as a separate process: `cd ~/Projects/adsbookcms && DEV_PROVIDERS_PORT=8788 npm run dev:providers`. The 99ribu side only knows the origin.
2. Add `scripts/local-providers.ts` with one subcommand `check`, run as `node --env-file=.env.example scripts/local-providers.ts check`:
   - requires `LOCAL_PROVIDER_ORIGIN` (via the S163 reader); missing or invalid: exit 1 with the exact start command;
   - `GET /` answers; `GET /api/public/local/address/search?keyword=jakarta` is an array with `_id` and `DISTRICT_NAME`; `GET /api/public/local/order/estimate?...courier=all` is an object keyed by courier; `GET /api/h2h/list_payment` with Bearer `local` has `rc` and a `data` array; after S171, `POST /api/h2h/create_payment` with a throw-away `reff_id` answers a `trx_id`;
   - prints the origin and, when `~/Projects/adsbookcms` is a git checkout, its `HEAD` short hash so evidence records which stand-in ran (informational, not a gate);
   - never prints a body that could carry a key (there is none, but keep the habit).
3. README registry rows: the start command, the check command, and a note that the stand-in forgets payments on restart.
4. **Tests start their own instance** on a free port found by probing, passed as `DEV_PROVIDERS_PORT`, and kill it in teardown, so a developer's long-running 8788 instance is never shared by a test (shared in-memory state collides across runs).
5. STATUS names the stand-in owner (AdsBookCMS) and the pinned expectation: "the stand-in at the recorded `HEAD` passes `check`".

Alternative rejected: vendoring the script into 99ribu (two copies drift; AdsBookCMS's `dev-providers.test.ts` guards only its own clients).

## Scope

In: `scripts/local-providers.ts`, README registry rows, `scripts/check-tests.ts` only if `check` is also exposed as a case, `.env.example` comment.
Out: any change to the AdsBookCMS repository (S171), the application code, any network beyond loopback.

## Allowed and protected paths

Allowed: `scripts/local-providers.ts`, `README.md`, `.env.example`, `package.json` (one script entry if used), `tests/*.test.ts` for the script. Protected: `src/**`, `migrations/**`.

## Test plan

- Stand-in up: `check` exits 0 and prints origin and `HEAD`.
- Stand-in down, variable unset, variable invalid, a non-JSON answer, a missing estimate key: each exits non-zero with a clear message and the start command.
- The check refuses any origin that is not the validated loopback one (reuses S163).

## Risks and escalation

- Cross-repository path assumption (`~/Projects/adsbookcms`); document it, do not hard-fail when absent (only skip the `HEAD` line).
- A moving AdsBookCMS branch can change the stand-in; the recorded `HEAD` is the only guard until S171 lands.
- Escalate if a test needs the stand-in to be shared across processes.

## Done when (runnable)

`node --env-file=.env.example scripts/local-providers.ts check` exits 0 with the stand-in running and non-zero with a clear message without it; README lists both commands; STATUS names the stand-in owner.
