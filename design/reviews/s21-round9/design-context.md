### Controls, data density and feedback
- Primary touch actions and icon buttons have at least a 44 × 44 CSS-pixel hit area as the project target; hit areas may exceed visible glyph size without overlapping adjacent controls. Form input and primary button defaults are at least 44px high, with multiline fields growing safely. Compact mouse/keyboard-only admin density is allowed only with a comfortable coarse-pointer mode.
- Admin table default is 48px minimum row height so 44px actions have nonoverlapping targets; multiline rows grow. A compact mouse/keyboard-only variation must not compromise touch-mode controls. Mobile transforms to prioritized list-detail or a deliberately scrollable table with visible critical identifiers/actions; do not shrink text to fit every column. Align monetary values to the end, keep headers/units and amount source/state visible.
- Use one clear primary action per local task; secondary actions remain available with explicit labels. Disabled controls explain the unmet condition; loading protects only the pending action and retains usable context. Destructive/financial confirmations show scope/consequence and existing domain guards.
- Inputs retain persistent labels, help/error association, entered safe values and visible focus. Error, loading, empty, filtered-zero, stale, partial and success states have distinct text and recovery. Status includes text/meaningful icon and time/source where applicable; role or financial state never depends only on color.
- Dialog/sheet and chat/image viewer keep named purpose, focus containment where modal, Escape/Back and focus restoration. Product/context cards reserve image dimensions, provide missing-image fallback and show full identity/option/contents; truncation always has an accessible way to recover essential text.
- Motion is limited to brief state feedback; no hover-lift in dense chat/order tables, no animation required to understand status, and reduced-motion users retain every action. New messages do not move focus or scroll old history away. Layering must never cover checkout confirmation, input errors, safe-area composer or focused controls.

Value comes from actual products and useful bundles. Selected under owner delegation on 2026-10-15; this is a composition contract, not a rendered branded mockup.

Portfolio scan inspected 12 recent project packages; Inter/Cinzel and a shared 0.625rem radius recurred in 11. Do not automatically reuse that pairing/template. - C1 Desktop storefront: compact brand/search/account/cart header; category navigation; short fixed-price proposition and optional single factual shipping offer; category discovery; product grid; factual purchase/return help; footer. Desktop mode retains its own hierarchy, starting with four comparable product columns at 1440px. - C2 Product detail: dominant real media next to a narrower purchase region on desktop; mobile has its own task header/media/variant flow and safe-area-aware purchase region, with shipping/return and category facts accessible in that journey; see the mobile composition contract below. Media is predominantly square for comparison, with uncropped detail views for fashion or tall packaging.
- C3 Cards: image, listing name, sellable-option/variant context, contents count when relevant, and Rp99.000 per selected option; include verified stock/claims only when useful. Quick add appears only for a fully specified purchasable variant. Category filters depend on actual attributes; no price-range filter for a fixed-price catalog.
- C4 Checkout: use the dedicated `/checkout` composition and state contract below; contact/address -> fulfillment breakdown -> shipping/payment choice -> final total; desktop summary beside form; mobile uses a focused checkout step flow with full package review before confirmation, rather than stacking the desktop layout. Every package shows origin, items, buyer-paid shipping, subsidy, estimated delivery and COD due when applicable. Expired or changed quote asks buyer to review revised totals.
- C5 Admin: sidebar plus contextual toolbar, immediate exceptions, then the work queue; row/detail view retains filters. Warehouse scope is visible. Payment, fulfillment and returns remain independent columns. Order overview does not require charts.
- C6 Affiliate: primary eligible balance and Rp99.000 payout-minimum explanation; separate pending/held/awaiting manual transfer/processing/paid amounts; referral link; item-level history with explanation and dates. Eligibility is computed automatically H+10 after verified buyer receipt; finance transfers manually in the initial release. There is no Withdraw button and no promise of instant or automatic bank transfer.
- C7 Open product grouping uses whitespace rather than elevated box frames. Low-radius form controls and lightweight table dividers support tasks. Do not substitute a giant centered marketing hero, generic bento dashboard, fake reviews, timer, invented scarcity or repeated promo popup.
