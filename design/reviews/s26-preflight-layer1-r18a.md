## Findings

**F1 — The same word, "ongkir", means two different amounts (material).**
- On the shipping step, `a34d…-shipping-subsidized-390-03` shows "Tarif paket tersimpan Rp27.000 / Subsidi −Rp3.000 / **Ongkir tersimpan Rp24.000**". Here "ongkir" is the net fee the buyer pays.
- On review, `e149…-review-subsidized-390-02` shows "**Ongkir paket Rp27.000** / Subsidi paket −Rp3.000 / Ongkir yang dibayar Rp24.000", and its totals show "**Ongkir 1 paket Rp27.000** / Subsidi ongkir −Rp3.000". Payment-expired does the same.
- So the buyer sees "ongkir Rp24.000" on one step and "ongkir Rp27.000" on the next, which looks like the price went up just before they confirm. This is the same class of problem as the canonical17 blocker; the fix only changed the chooser.
- Fix: use "Tarif" for every gross amount (review card, totals rows, summary, payment views) and keep "Ongkir" only for the buyer-paid net amount.

**F2 — The allocation-pending alert sends the buyer to a button that is not on screen.**
- In `9822…-allocation-changed-390-01/02` the alert says "Tinjau pesanan untuk memperbarui layanan dan total". The only action on that screen is "Perbarui pembagian paket".
- In `6840…-shipping-two-origins-nojs-390-01`, a grey "Pembagian paket diperbarui." sits directly above a warning saying the stored calculation is not up to date. The two messages contradict each other.
- Fix: write alert copy for each state and name the action that is actually on screen.

**F3 — Clipped destination select.** This is the select row in the table above. The hierarchy line underneath limits the harm, but clipped rendering still counts as a finding.

**Evidence note (not a design defect).** The fixtures change between viewports: the shipping step shows Rp210.000 at 390, Rp213.000 (COD) at 768 and Rp225.000 at 1024/1440. Because of that, the breakpoint renders can't be compared for the same order.
